Purpose

AI systems fail fast when stakeholders don’t trust the numbers. Metrics exists to remove ambiguity and make the funnel explainable — so leaders can act with confidence.

  • Single source of truth: one definition per metric, enforced via the Metrics Dictionary.
  • Event-based analytics: timestamps and stage events (not spreadsheet guesswork).
  • Guardrails: SLA drift, data quality issues, and process decay show up early.

What it measures

Metrics is organized into families so different audiences can get the right slice of truth.

  • Funnel: volume, stage counts, pass-through
  • Speed: time-to-fill, time-in-stage, time-to-offer
  • SLA health: scorecard compliance, scheduling speed, update coverage
  • Capacity: recruiter/HM load, plan vs actual, pipeline sufficiency
  • Quality proxies: offer rates, calibration drift, override patterns

Where it fits in the suite

Metrics is downstream from Hiring & Mobility, and upstream of Planning and Innovation.

  • Feeds Planning: forecast accuracy, capacity warnings, weekly agendas.
  • Feeds Innovation: what experiments worked, where process decay is happening.
  • Reports to Chief: thresholds for autonomy + escalation triggers.
  • Improves Hiring: pass-through anomalies, SLA breaches, bottleneck diagnosis.

Guardrails

Metrics doesn’t replace human judgment — it keeps the system honest. When the numbers drift, it’s a signal to investigate before trust erodes.

  • Definition governance: changes to metrics require review + changelog.
  • Data quality: missing timestamps, stage hygiene, timezone consistency.
  • Auditability: drill-down views show event sources and calculations.
