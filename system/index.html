System Overview

The system is organized around four lifecycle stages — Hire, Support, Evaluate, Improve. The differentiator is the shared architecture underneath: the same definitions, evidence model, and guardrails show up everywhere.

Shared Architecture

Every stage uses the same underlying components so insights are actionable, decisions are consistent, and automation is safe and reviewable.

Signals

Inputs that are consistent, named, and comparable across workflows.

  • Metrics + throughput + SLAs
  • Open-text + themes + reasons
  • Capacity constraints (HM/recruiter/interview loops)
  • Risk indicators + drift detection

Decision Logic

Turn signals into “what to do next” — not just reporting.

  • Thresholds + expected ranges
  • Root-cause prompts (“why this surfaced”)
  • Recommended actions + impact tradeoffs
  • Escalation rules when stakes increase

Auditability

Every recommendation/action is explainable and reviewable.

  • Receipts and evidence attached
  • Human approvals where needed
  • Action logs + change history
  • Guardrails by autonomy tier

Governance & Safety

AI is assistive by default. Autonomy is explicitly tiered to protect people, decisions, and organizational trust — with auditability built in.

Guardrails on AI Autonomy

What can safely auto-execute, what requires approval, and what must always escalate.

Tier 0 — Monitor Baseline measurement + drift detection only. No action.
Tier 1 — Auto-execute (low risk) Reminders, routing, refreshes, nudges, task creation. Logged and visible.
Tier 2 — Recommend (approval required) Actions affecting outcomes require explicit human approval.
Tier 3 — Escalate (high risk) Employment-impacting decisions are never automated; governance applies.
