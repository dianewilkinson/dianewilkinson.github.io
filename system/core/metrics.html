Core: Metrics Dictionary

A single source of truth for metric names, definitions, formulas, grain, filters, and ownership — so dashboards stay consistent, analyses are auditable, and decisions are repeatable.

Why a dictionary is “core”

Most reporting failures aren’t “dashboard problems” — they’re definition drift: different teams calculate the “same” metric differently (filters, grain, time rules, data source fields), and the organization loses trust in the numbers.

Consistency One metric name → one definition → one formula. No local interpretations.
Auditability Every metric documents grain, filters, data source fields, and refresh cadence.
Actionability Each metric includes interpretation notes to connect signals to decisions.
Design intent: the dictionary is tool-agnostic. It can power dashboards, scorecards, weekly business reviews, and A[i]gent decision logic.

Related

The dictionary is the contract between data, analytics, and operators. Tools can render and apply it, but the dictionary itself is the governance layer.

Format: ID, group, definition, formula, numerator/denominator, grain, filters, data fields, owner.

What’s inside the Metrics Dictionary

  • Metric ID + Group: stable identifier and domain grouping for navigation and change control.
  • Definition + Interpretation: what it means and what movement usually implies.
  • Formula + inputs: explicit numerator/denominator and calculation logic.
  • Grain + filters: what level the metric is valid at (candidate, req, employee, day/week) and which filters apply.
  • Data mapping: where the metric lives (object/field) and which system is the source of truth.
  • Governance: owner, refresh cadence, and target (when applicable).

Governance and change control

  • Definition changes are versioned: a metric’s meaning should not change silently.
  • Owners are named: every metric has a steward responsible for correctness and fit-for-use.
  • Time rules are explicit: reporting timezone, source timezone, and local time entity are documented.
  • Dashboards reference IDs: charts point to metric IDs to reduce drift across teams.
