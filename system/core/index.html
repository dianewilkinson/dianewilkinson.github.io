What lives here

The Core is the contract across the whole portfolio. Tools reference it — they don’t redefine it. This is how you get repeatability, auditability, and trusted decision-making across teams.

Definitions Shared meanings for terms like “pipeline health,” “capacity,” “quality,” and “signal.”
Logic How a signal is calculated + how it should be interpreted in context.
Thresholds What triggers a flag, a recommendation, or an escalation path.
Ownership Who can change a definition, why, and how changes roll out safely.

How the Core works in practice

Tools sit on top of shared signals. When the Core is stable, teams can move fast without breaking trust.

Rule of thumb: If two people can look at the same metric and tell two different stories, you don’t have a metrics problem — you have a Core problem.

Core → Tool → Action

  • Core defines the signal (what it is, how it’s computed, when it matters).
  • Tools operationalize it (dashboards, A[i]gent flows, recommendations).
  • Action is governed (safe Tier-1 autonomy, escalation, audit trail).

What you’ll see as this fills in

  • A clear dictionary of shared signals (with formulas + interpretation notes)
  • Decision thresholds tied to recommended actions
  • Change control so updates don’t silently break downstream tools
